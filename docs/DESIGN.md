## 1. Workspace anatomy

```
┌────┬─────────────┬───────────────────────────────┬───────────────┐
│ A  │ CHAT LIST   │ CONVERSATION                  │ FAN PANEL     │
│ c  │             │ header: name · lastSeen ·     │ (collapsible) │
│ c  │ filters:    │   value chips ($ total, sub)  │ tabs:         │
│ t  │ All/Unread/ │                               │  Info         │
│ s  │ Tips        │  virtualized message list     │  Summary (AI) │
│    │ search ⌘K   │  day separators               │  Notes        │
│ ▾  │             │  money events stand out       │               │
│    │ virtualized │  send-state glyphs            │ spend chips   │
│    │ rows:       │ ┌───────────────────────────┐ │ sub status /  │
│    │ avatar,     │ │ AI DOCK (collapsible)     │ │ churn badge   │
│    │ preview,    │ │ streams; Insert/Copy/parts│ │ last seen     │
│    │ time,       │ └───────────────────────────┘ │ custom name   │
│    │ badges      │ composer · tones · send ⌘↵    │               │
└────┴─────────────┴───────────────────────────────┴───────────────┘
```

- **Account rail (A):** avatars with unread badges; switch <500 ms (budget). Aggregate badge on app icon.
- **Chat list:** ~340 px, rows ~64 px, virtualized. Minimal chrome (owner): no list title, no per-list sync label (freshness lives in the status bar only); a single quiet filter row — All / Unread / With tips; search/jump only via the ⌘K palette. "Fan waiting" indicator per PRD F2. **Fan value in the row** (owner-settled 2026-06-11 after four side-by-side experiment rounds; scratch experiment pages live untracked in `mockups/experiments/` — only the binding mockup is committed): **lifetime spend right after the name** — bare mono figure by default (10.5 px `--t-mid`), bordered chip via a **per-chatter display setting** (`spendStyle: figure | chip`); the name truncates first, the figure survives. **30-day spend bottom-right as a bare green `+$120`** (10 px mono semibold `--green`, no label — tooltip explains the window) beside the unread badge — the row's single colour accent: **green marks recent money inflow, never stock**. Exact dollars with thousands separators everywhere, matching the header chip and fan panel; $0/unknown renders **nothing** — silence is the signal. Rejected along the way (kept in the gallery's "rejected" section): right-column totals, K-notation, whale tiers (bold or colour), the separate tip pill, green badge recolouring, the `· 30D` label. The unread badge is always clay; tips read via the Tips filter and the preview line (owner: chatters work primarily through OnlyMonster — this app is a companion, signals must not scream). Data: lifetime from `fans.spending.total` (every list-chats poll); 30-day aggregated at read time from the local `fan_transactions` store, fed at once by Core's `transaction.posted` facts (D39, same transaction id — never counted twice) and by an incremental `GET /{account}/transactions` sweep (first walk `-30days`, then from the newest row the sweep itself read − 1 h overlap; 10-min cadence, ≈1 credit per sweep at steady state — see `sweepFanSpend` in polling-sync). **All money figures are creator-NET (owner decision 2026-06-13):** OnlyFans reports `fans.spending` net of its 20% cut, so the 30-day figure sums transaction `net` (fallback `0.8 × amount`) — never the gross `amount`; mixing the bases made the green figure exceed the lifetime for fans younger than 30 days.
- **Conversation:** virtualized list; PPV state badges unmissable (purchased = filled, not purchased = outline); tips highlighted; send-state glyphs (sending → sent → seen / failed / unconfirmed). Reply-to context inline.
- **AI surface (redesigned 2026-06-10 after owner feedback).** Three tiers of access: **(1) composer pill row — all five frequent actions, always visible**: `✳ Reply ⌘R · Improve ⌘I · Help ⌘H · Ping ⌘P · Hi ⌘G` (owner: Ping/Hi are frequent — keep them at hand; when inapplicable they dim with the reason in a tooltip — fan-active for Ping, >10 msgs for Hi — matching legacy gates); **(2) the `✳ AI` menu in the conversation header — rare/deep actions only**: **Scan ⌘S** (deep fan profile → panel's Scan tab; "Scan" is the team's name for fan-summary, the legacy UI label — `chatgoose: src/content/button-bar.ts:10`), Chat review ⌘E, Compare; **(3) the ⌘K palette** (every action by name). Analysis outputs (Review, Help coaching) render in the dock as read-only serif cards — only true reply drafts get the insert affordance. Active state = dock above the composer, never a modal: suggestions render as **draft message bubbles** (serif text, dashed terracotta border) — **clicking the bubble inserts it** (the whole card is the target; a quiet `INSERT` chip sits inside — individual parts are click-only since `⌘1..9` now jump chats), `⌘0` inserts all parts; footer = tone pills (Fast Reply only, re-toning an already-open dock) + Regenerate; cost appears top-right after completion; streaming = caret in the text; dismiss = ✕ / Esc. **Tone is selectable BEFORE the first generation (variant C, owner-approved 2026-06-13):** the `✳ Reply ⌘R` pill is a **split control** — the body generates a fast-reply in the active tone (`⌘R`, unchanged), and a small **▾ caret** opens an upward popover menu listing the four tones (casual / flirty / upsell / spicy) with the active one marked; **clicking a tone generates immediately in it** (one action = one toned reply, no wasted "normal" run) and closes the menu (Esc / outside-click also close). The active tone is **sticky within the chat and resets to the default when the chat changes** (no leakage to the next fan); the menu mark, `⌘T` cycling, and the dock footer pills all reflect the same effective tone. **The menu only drafts into the dock — it never sends** (SPEC §15: AI never sends without explicit human action). **No model/TTFT telemetry in the UI** — that lives in debug mode only.
- **Fan panel:** collapsible (`]`), two tabs (Info / Scan); money chips (total / tips / messages / subs), auto-renew-off ⇒ churn-risk badge.

## 2. Interaction model & hotkeys

Goal: **a full shift without touching the mouse.** Core triage loop: `⌘U` (next unread) → read → `⌘R` (fast reply) → review/edit → `⌘↵` (send) → `⌘U` …

| Key | Action |
|---|---|
| `⌘K` | Command palette: jump to chat/fan/account, run any action |
| `J / K` (list focused) / `⌘U` | Next/prev chat / next unread |
| `Enter` / `Esc` | Focus composer / blur·dismiss dock |
| `⌘↵` | Send |
| `⌘R` / `⌘I` / `⌘H` | Fast Reply / Improve Draft / Help Me |
| `⌘P` / `⌘G` / `⌘E` / `⌘S` | Ping / Hi greeting / Chat review / Fan summary (when applicable) |
| `⌘1..9` | Jump to chat N — first nine of the current filtered list (hold the mod key to number the list) |
| `⌘0` | Insert all AI draft parts as a `[NEXT]` sequence — individual parts are click-only (companion phase: copy) |
| `⌘.` | Cancel running AI operation |
| `⌘T` | Cycle tone (casual/flirty/upsell/spicy) — or pick directly from the Reply ▾ split-menu (which also generates); `⌘R` always replies in the active tone |
| `]` / `[` | Toggle fan panel / chat list |
| `?` | Hotkey cheatsheet overlay |
| `⌘,` | Open settings (any view) |

All hotkeys also reachable via the palette; keymap centralized (single registry, no scattered listeners). The app sets a custom application menu (main): Electron's default menu would shadow `⌘R`/`⌘H`/`⌘0` with Reload/Hide/Actual-Size accelerators before the renderer keymap sees them — Hide lives on `⌃⌘H`, Reload exists only unpackaged on `⇧⌘R`, zoom roles are dropped (UI scale is a setting), Edit clipboard roles stay.

Hotkey **labels** are platform-aware (PLAN item 11, 2026-06-13): every rendered mod-key label flows through the `lib/modKey.ts` seam — `⌘K` on macOS, `Ctrl+K` on Windows/Linux; never hardcode the ⌘ glyph in a component. Matching was always platform-agnostic (`mod` = metaKey || ctrlKey), so combos and behavior are identical everywhere. This doc and the mockups keep writing `⌘` as shorthand for the mod key.

## 3. Performance engineering — how the SPEC §13 budgets are met

This section is review-blocking for renderer PRs, same weight as SPEC §15 invariants.

1. **Cache-first paint.** Cold start renders the inbox from SQLite before any network; network results reconcile through the DB → change-subscription path, never direct `setState` from fetch handlers. Single source of truth = DB (SPEC §6.3).
2. **Virtualize both long lists** (`@tanstack/react-virtual`): chat list and message history. Memoized rows, stable keys, measured-height cache; scrollback fetches pages of ≤100 from main.
3. **IPC discipline:** renderer receives narrow typed view-models, never raw OFAPI JSON blobs; queries are paginated; DB-change notifications batched (≤1 flush / 50 ms — the legacy stream-batching lesson). No polling loops in the renderer; main pushes.
4. **AI streaming without re-render storms:** stream chunks append via direct text-node updates inside the dock (legacy overlay technique) with 50 ms batching — the React tree around the streaming card must not re-render per chunk.
5. **Media pipeline:** thumbnails through the `media://` handler with disk LRU (SPEC §10); `loading=lazy`, `decoding=async`; dominant-color/blurhash placeholders; full-size media only on click; image decode must never block scroll.
6. **State discipline:** Zustand with per-slice selectors (no whole-store subscriptions); TanStack Query structural sharing for IPC reads; no app-wide context providers that re-render the tree; React StrictMode + Profiler pass per feature.
7. **Main-thread budget:** any renderer task >16 ms is a defect; JSON parsing, diffing, search indexes live in main (or a worker if ever needed). Long-task monitoring on in debug builds.
8. **Animations:** transform/opacity only, 150–200 ms, reduced-motion respected; none during streaming or fling-scroll.
9. **Electron config:** single BrowserWindow; `backgroundThrottling` disabled for the timer that drives slowed hidden-window polling (SPEC §6.1 — notifications must fire in companion mode); preload kept minimal.
10. **Perf smoke test in CI (from P1):** scripted scroll over a 10k-message fixture asserting frame budget, plus startup-time measurement; budgets from SPEC §13 are the thresholds.

## 4. Visual direction — "Claude-style warm professional" (chosen by owner 2026-06-10)

- **Light is the default; an optional dark theme ships alongside it (owner decision 2026-06-13 — `uiTheme: system | light | dark`, Settings → Behavior → Theme; default `light`, opt-in).** Anthropic-like warm palette: cream window `#efece4`, ivory panels `#faf9f5`, warm hairlines (`#e2dfd3`/`#cfcaba`), soft shadows, 7–14 px radii, pill-shaped chips, asymmetric bubble corners (flat side toward the sender). **Dark is a pure CSS-variable swap (`.dark` on `<html>`, overriding the `--color-*`/`--shadow-*` tokens in `renderer/src/styles/index.css`) — same warm hue family, accent terracotta unchanged across themes; main mirrors it via `nativeTheme.themeSource` + the window pre-paint `backgroundColor`. Dark token block in `index.css`; experiment page `mockups/experiments/dark-theme.html`. Semantic greens/ambers are lifted for legibility on dark ground; all hierarchy/flatness rules below hold in both themes.**
- **Terracotta `#d97757`** (hover/deep `#c2603f`) for primary actions and attention: Send, active account, selected-row bar, unread pills, active tone chip, "fan waiting" dots, the AI spark.
- **Money = financial green** (`#3a7d44` on `#e9f1e5`): lifetime/value chips, tip ledger rows, purchased-PPV badges, credit/LLM figures in the status bar. **Pending money = amber** (`#96691c`, unopened PPV). Other semantics: seen `#4a72b8`, warn `#b45309`, failed/churn `#bb4430`, online `#3f9e54`.
- Typography: **Hanken Grotesk** (UI) + **Source Serif 4** for headings (wordmark, section titles, fan names) **and for all AI-authored text** — dock outputs, AI summaries — the "machine speaks in serif" signature; **IBM Plex Mono** for numerals, timestamps, send-states, micro-caps; tabular numerals for money and time. **Type floor (owner feedback): 14 px base, 14.5 px message text, 10 px micro-labels.**
- Send states as terminal-style mono micro-labels: `SEEN 18:42` / `SENT` / `UNCONF` / `FAILED`.
- Density over decoration: flat scannable rows, information-dense but calm (PRD §7.6).
- Custom design system in `src/renderer/design/` (tokens + primitives: Button, Chip, Badge, ListRow, Skeleton, Toast, Dock). **No heavy component library**; no generic "AI-generated SaaS" look (gradient heroes, glassmorphism, decorative blur) — restraint, craft, speed.
- Anti-goals: no modal dialogs inside the shift loop; no avatar noise in dense lists beyond the chat row. (Dark theme is no longer an anti-goal — it shipped as an optional CSS-variable swap, owner 2026-06-13; the discipline is that it stays a pure token re-skin, never per-component dark styling.)

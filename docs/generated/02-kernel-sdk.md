# ChatGoose Desktop — The Vendored Kernel SDK (`@kernel/sdk`)

`packages/kernel-sdk` is the **compiled, vendored client for the core hub's API**. It is
the single mediating layer for the desktop's one privileged boundary (see `01`). This
map describes what it is, its surface, the pin that keeps it honest, and the exact
request/frame shapes that cross it. It is a **generated artifact** — never hand-edited.

## What it is

- Package `@kernel/sdk`, private, `workspace:*` dependency of both `@chatgoose/desktop`
  and `@chatgoose/shared`. Single dependency `zod`; single export `.` →
  `dist/index.js` (`packages/kernel-sdk/package.json`).
- **Vendored dist only** — `packages/kernel-sdk/dist/**` (`.js` + `.d.ts`), no source. The
  `package.json` description and `README.md` state it is "generated by core
  `scripts/vendor-sdk.mjs` — do not edit." It is re-vendored from the core repo when the
  desktop needs new operations.
- Provenance is recorded in `packages/kernel-sdk/kernel-sdk.vendor.json`:
  `contractHash: ea3d41824ff9cf56502da0b91934de8147ae68025b958a960b01365fb145891c`,
  `sourceCommit: bac302081c80b13674f1177dc9cb4fc043b5441e`,
  `source: core scripts/vendor-sdk.mjs`.

## dist layout

- `dist/index.{js,d.ts}` — the barrel (export surface below).
- `dist/meta.{js,d.ts}` — `KERNEL_CONTRACT_HASH` (the same sha256 as the vendor manifest)
  and `KERNEL_SDK_VERSION = "0.1.0"`.
- `dist/operations.{js,d.ts}` — `kernelOperations`, the exhaustive operation → `{ method,
  path }` map (~130 operations).
- `dist/contracts/*` — the runtime: `sdk-runtime.{js,d.ts}` (fetch/SSE engine, auth

  `authorization-policy.*`, `domain-event-cursor.*`, and `contracts/index.*`.
- `dist/shared/*` — shared types pulled in from core.

## Export surface (`dist/index.d.ts`)

- **Client factory:** `createClient(options)` / `createKernelClient(...)` returning a

- **Contract identity:** `KERNEL_CONTRACT_HASH`, `KERNEL_SDK_VERSION`.
- **Types:** `KernelClient`, `KernelOperationKey`, `KernelOperationRequest`,

## The exact shapes that cross (schemas)

- **AI feature request** (`aiFeatureStreamBodySchema`,
  `dist/contracts/routes.d.ts`, `z.core.$strict`): `{ clientRequestId, pageLabel,
  platform:'onlyfans'|'fansly', conversationRef, fanRef?, personaKey?, model?,
  reasoningEffort?, replyTone? (none|casual|flirty|upsell|spicy), replyMode?
  (default|preferSplit), messageCount?, draftText?, isRegeneration? }`. This is refs +
  client-side draft/tone only — no prompt or transcript.
- **AI SSE frame** (`aiGatewayStreamFrameSchema`, discriminated on `type`): `meta`,
  `content_delta`, `reasoning_delta`, `usage`, `error`, `done` (fields enumerated in `01`
  §3 and `08`). The runtime keeps only SSE frames whose `event === "ai"`; heartbeat
  comment lines and `retry:` hints are skipped.
- **Command / event / ingest / profile bodies** are validated by `routeSchemas.*` (e.g.
  `routeSchemas.createOfapiCommand.body`, `routeSchemas.ingestObservations.body`,
  `routeSchemas.aiFeatureStream.body`), which the shared client uses for pre-wire
  "would-400" rejection (`packages/shared/src/hub/client.ts`).

## Streaming / SSE runtime (`dist/contracts/sdk-runtime.js`)

- `streamAiFeature`/`streamAiGateway` open one SSE connection each and **do not
  auto-reconnect** (the server bounds the connection lifetime; consumers own the reconnect
  loop). Resume is via a `last-event-id` header.
- `subscribeSyncEvents`/`subscribeDomainEvents` back the hub-sync loop (`06`); the desktop
  drives v2 with an opaque cursor rather than the SDK's own subscribe helper in the hot
  path (see `06` for which is actually used).

## The pin and its two drift gates

The contract hash is the cross-repo drift key. Two gates run inside `pnpm check` on every
PR:

1. **Vendor pin test** — `packages/shared/tests/kernel-sdk-vendor.test.ts` asserts the
   `kernel-sdk.vendor.json` `contractHash` equals the SDK's exported
   `KERNEL_CONTRACT_HASH`. This catches a partial or hand-edited vendor.
2. **Typecheck** — a renamed/removed operation fails compilation at every call site, so a
   breaking contract change cannot land silently.

Re-vendoring is a core-side operation (`scripts/vendor-sdk.mjs
../onlyfans-chat/packages/kernel-sdk`) committed here as its own change; the
`dist` and `.vendor.json` are never edited by hand.

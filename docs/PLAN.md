## Target end-state architecture (north star) — articulated 2026-06-19

> **Not a rewrite, not new scope — the coherent end-state that the ALREADY-PLANNED pieces add up to** (P6 AI gateway + runbook №4 OFAPI key-custody proxy + the parallel-track SSE). Articulated after the 2026-06-19 webhook-migration audit; full reasoning + file:line evidence in repo-root **`opus_multi.md`**. The seam already exists: SPEC §5(d) makes direct↔gateway a config switch (base URL + auth header) on the single `OfApiClient` chokepoint, so this is config-plus-thin-proxy, incremental behind the existing `SyncProvider` seam.

**Principle — single trust boundary:** core is the ONLY holder of secrets (OFAPI key, LLM keys) and the ONLY component that talks to OFAPI and the LLM providers. Desktop is a **thin local-first replica** that talks ONLY to core (SSE tail for reads · REST intents for writes · streamed AI). It holds ONE secret — the chatter token for core — never a god-mode OFAPI key.

**Why (verified drivers):** (a) OFAPI keys have NO scopes — every key = full access to every connected account (SPEC §5); §5(b) already mandates *"desktops hold no OFAPI key"* before scaling past the supervised pilot. (b) Desktop is behind NAT → can't receive webhooks → a relay (core) is mandatory, not a choice. (c) It collapses the dual-OFAPI-client problems the audit surfaced: split spend accounting (desktop meters only its own calls; webhook cost lives only in core), two freshness clocks (poll vs SSE → the dishonest "обновлено Xs назад"), and duplicate polling. Today there are genuinely TWO OFAPI clients (each desktop + core); the end-state has ONE.

**Migration delta (each step is independent, behind the `SyncProvider`/`OfApiClient` seams):**

| Today | Target | How |
|---|---|---|
| Desktop holds `ofapiKey`, calls `app.onlyfansapi.com` directly | core = sole OFAPI client; desktop holds no OFAPI key | move `OfApiClient` base-URL to a core gateway (runbook №4; §5(d) config switch + thin proxy in core) |
| Desktop holds `anthropicKey`/`openRouterKey`, calls Anthropic directly by default | AI via core gateway, tokens streamed through | desktop HubGateway is wired behind rollback; live-validate the default-off core gateway before removing local keys |
| SSE replay only within the 7-day journal; longer offline → silent gap repaired by ~6 h reconcile | snapshot + tail (correctness by replay, not by eventual reconcile) | core: add a `state since seq=N` snapshot endpoint; desktop resumes the SSE tail from it |
| Two OFAPI clients → split spend accounting | one unified credit + AI ledger in core | follows from the gateway; desktop credit-meter is then removable |
| Desktop poll-freshness + SSE liveness = two clocks | one cursor (last applied seq) = one freshness clock | follows from "core is the only producer of changes" |

Honest trade-off: core availability becomes load-bearing (no desktop→OFAPI fallback). Mitigated by (a) the already-required move of core off the laptop tunnel to a stable host, (b) the local SQLite replica keeping all history readable during core downtime (degraded = "no new data", not "dead"), (c) a write outbox. This is strictly better than the current "every laptop carries a god-mode key as a fallback".
